# Оптимизация правил одной комнаты

```sh
dotnet run -- train --generations 50 --population 32 --steps 60 --output best-room.json
dotnet run -- play best-room.json
dotnet run -- play best-room.json --animate --delay 40
dotnet run --project tests/HelloWorld.Checks.csproj
```

Исходная комната одинакова для каждого кандидата и каждого поколения. На границе
четыре дверные клетки `Road`, в центре существующий `Hub`, внутри две начальные
клетки `Obstacle`. Размер по умолчанию 30 × 20. Граница, двери и хаб неизменяемы;
новых типов клеток нет. Числовой запуск `dotnet run -- 25 30 20` открывает
текущее отдельное демо автомата (Conway's Game of Life).

## Запуск симуляции

Каждого кандидата запускаем на фиксированное число шагов `--steps`. Автомат
вероятностный: одинаковый `--simulation-seed` задаётся каждому новому прогону.
`--search-seed` независимо управляет генетическим поиском. Повторение команд с
одинаковыми настройками воспроизводит результат на том же .NET runtime.

Не завершаем прогон по неизменной картинке: внутри продолжают накапливаться
счётчики `lifetime`, а вероятность может сработать позже. В существующем ядре
`lifetime` накапливается при выполнении условия, не сбрасывается при его
невыполнении и проверяется до увеличения. Обвязка сохраняет эту семантику.

## Что оптимизируем

Геном содержит пять условий из `RuleTrainer.InitialRules`: рост дороги от хаба,
рост дороги от дороги, рост препятствия от препятствий, очистка переполненной
дороги и очистка препятствий возле пустоты. Эволюционируют `count`, `lifetime`,
`chance` и приоритет условий. Это ограниченный поиск параметров и порядка этих
переходов, а не произвольных программ правил. Порог 9 отключает условие, поскольку
у клетки не более восьми соседей. Смена дороги прямо на препятствие и обратно
исключена. Дорога может исчезнуть, после чего освободившаяся клетка участвует в
обычных переходах.

Автомат считает восемь соседей; метрики проверяют связность по четырём сторонам,
поэтому соприкосновение по диагонали не соединяет дороги или кластеры.

Fitness сравнивается лексикографически:

1. Число дверей, достижимых из хаба по `Road`/`Hub`.
2. Средний прогресс приближения компоненты хаба к дверям:
   `1 - distance(door, component) / distance(door, hub)`, где расстояние манхэттенское.
3. Среднее шести оценок композиции: заполненность дорогами и препятствиями,
   число и компактность кластеров, отсутствие мелких кластеров и оторванных дорог.

Заполненность считается только по внутренним клеткам, `Hub` не входит в долю
дорог. Граничные стены не участвуют в компонентах препятствий. Оторванные дороги
считаются по всем `Road`, включая ещё не подключённые дверные клетки.
Компактность кластера — `16 * area / perimeter²`; периметр считается по сторонам
клеток. Кластеры меньше `minimumClusterArea` считаются мелкими. При отсутствии
препятствий их компактность и доля мелких кластеров равны нулю.

Для интервальных метрик `score = max(0, 1 - distance(value, [min,max]) / falloff)`.
Начальные интервалы — гипотеза о желаемой композиции, не доказанное определение
красоты. Высокая связность сама по себе не гарантирует узких дорог или хорошей
композиции. Все исходные метрики сохраняются вместе с fitness.

Настройки оценки можно передать через `--evaluation evaluation.json`:

```json
{
  "roadFraction": { "minimum": 0.08, "maximum": 0.22, "falloff": 0.8 },
  "obstacleFraction": { "minimum": 0.15, "maximum": 0.35, "falloff": 0.35 },
  "clusterCount": { "minimum": 2, "maximum": 6, "falloff": 6 },
  "clusterCompactness": { "minimum": 0.25, "maximum": 1, "falloff": 0.25 },
  "minimumClusterArea": 3
}
```

## Свой фиксированный сценарий

`--width` и `--height` меняют стандартную комнату. Для явного задания координат
используйте `--scenario scenario.json` вместо этих параметров:

```json
{
  "width": 15,
  "height": 11,
  "doors": [{ "x": 0, "y": 5 }, { "x": 14, "y": 5 }],
  "hub": { "x": 7, "y": 5 },
  "obstacleSeeds": [{ "x": 4, "y": 3 }, { "x": 10, "y": 7 }]
}
```

## Поиск и сохранение

Популяция по умолчанию 32, элита 2, турнир 3, вероятность мутации каждого
параметра 0.2. Остальные кандидаты получаются одноточечным скрещиванием и мутацией.
Обучение заканчивается после `--generations` поколений либо `--patience`
поколений без улучшения. Параметры: `dotnet run -- --help`.

При каждом улучшении атомарно перезаписывается `--output` (по умолчанию
`best-room.json`). Артефакт содержит сценарий, оба seed, число шагов, параметры
поиска и оценки, лучшие правила, поколение находки, метрики, fitness и итоговую
сетку (`.` пустота, `#` препятствие, `+` дорога, `H` хаб).

`play` заново выполняет симуляцию и проверяет точное совпадение сетки, метрик и
fitness с сохранёнными. Несовпадение возвращает ненулевой код завершения.
Артефакт сохраняет победителя; возобновление популяции не реализовано.
